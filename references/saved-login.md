# 已保存凭据登录

本文说明浏览器已有自动填充时的通用处理方法，不包含任何站点、账户或个人授权。使用时以用户实际授权的任务范围为准；安装本 skill 或连接调试端口不授予登录、业务提交或账户修改权限。

## 判断与操作

1. 优先复用现有登录。不要为验证自动填充而退出账号、清除 Cookie、重启浏览器或改变密码管理器设置。
2. 核对目标 origin、预期账户和唯一可见的登录表单。页面可能有多个同 ID 的隐藏表单，不能仅凭 `getElementById` 选取对象。需要用户选择账户时，不猜测或轮试其他账户。
3. Chrome 可能已经显示自动填充，输入匹配 `:-webkit-autofill`，但脚本读取的 `.value` 仍为空。结合可见页面与自动填充状态判断，不直接把空值写成“用户未填密码”或“浏览器没有保存密码”。不点击显示密码，不把密码、Cookie 或令牌写入脚本、输出或日志。
4. 普通 DOM `.click()` 未使填充生效时，可由支持页面输入的 CDP 客户端完成正常页面点击：在当前授权 origin 内定位唯一可见的按钮并取视口坐标，依次发送 `Input.dispatchMouseEvent` 的 `mouseMoved`、`mousePressed` 和 `mouseReleased`，左键、`clickCount=1`。不使用系统鼠标键盘，不激活窗口。若空值校验清空了账号，只能补回用户或当前任务已经明确确认的预期账户。
5. 登录后确认已离开登录页、进入预期业务页面，并核对预期账户。HTTP 200 本身不足以证明成功。超时或结果不明时先只读检查，不自动重放登录；出现密码错误或尝试次数警告时停止重试。

## 当前实现范围

`browser-bg` 1.6.1 起提供受限的 `cdp` 页面输入接口，可通过当前任务的 socket 发送 `Input.dispatchMouseEvent`、`Input.dispatchKeyEvent`、`Input.insertText`，或读取 `Page.getLayoutMetrics`。接口复用附着会话并在操作前检查 origin；它不授予登录、提交或账户修改权限。不能把 `eval` 中的 `.click()` 描述为已经发送了页面鼠标事件，也不为使用输入接口而放宽浏览器安全设置。使用时按当前 DOM 核对目标，不照抄历史坐标。

`navigator.credentials.get()` 无返回或超时不能代替实际登录测试，也不是使用已有自动填充的必需步骤。不要导出、解密或复制浏览器密码库来替代正常登录。

## 用户介入与验证边界

人机验证、Windows 解锁、生物识别及额外身份确认由用户完成，不绕过；完成后继续已经授权的后续任务。普通账号登录和业务提交分别判断权限。

已验证浏览器已有可见自动填充时，可通过页面鼠标事件完成普通登录。这不证明从空白表单开始、全程最小化的自动填充与登录流程已经通过验证。隐藏页面不适合用户必须看到和手动处理的登录或验证步骤。
